# 水稻施肥处方图生成系统（重构版）

无人机多光谱影像 → 营养诊断 → 大疆兼容施肥处方图，带本地 Web 界面的一体化工具。

原命令行项目（`code/` 下的 `diagnose.py` / `prescription.py` / `direct_generate.py` / `dj2pr.py`）
重构为一个网页应用，并修复了输入模型错误等问题（见下文「相对原项目的变化」）。

---

## 快速开始

```
双击 启动处方图系统.bat
```

或手动运行（需含 numpy / rasterio / pillow / flask 的 Python 环境）：

```
D:\miniconda3\envs\farm_edge\python.exe app.py
```

启动后自动打开浏览器访问 `http://127.0.0.1:8765`（端口可在 `config.json` 修改）。

## 使用流程

1. **数据接入**：拖拽 / 选择 5 张同经纬度 tif 影像上传，或填写文件夹路径直接引用
   （大影像建议用文件夹方式，免拷贝）。系统按文件名自动识别通道。
2. **校验**：检查通道完整性、波段数、尺寸与坐标一致性；生成整体预览图。
3. **感兴趣区域规划（可选）**：在预览图上点「✏️ 编辑感兴趣区域」进入编辑模式：
   * 左键标点（任意顺序，自动构成最小凸包），标点经纬度实时记录；
   * 左键点已有标点可删除该标点，凸包按剩余标点重算（凸包可内缩）；
   * 右键完成当前区域，继续左键可标注下一个区域；
   * 「撤销上一点」在当前区域为空时撤回最后一个已完成区域（其标点恢复为进行中区域，可继续编辑）；
   * 新区域的标点不能落在已完成的区域内部（自动拒绝并提示）；
   * 支持撤销上一点、取消当前区域、删除单个区域、清空全部。
4. **参数**：选择生育期（8 个模型）、生成范围（全图制作 / 感兴趣区域制作）、
   施肥映射方式（公式 / 手动）、重采样栅格设置（手动选择栅格宽度，最低 1 m，
   默认 1 m；average 像元面积加权平均，基于地理地面距离）。
   感兴趣区域制作时，可点击右侧「👥 编辑分组」进入分组模式：在感兴趣区域列表中
   勾选区域后点「＋ 添加为分组」即组成一个分组（可重复操作建立多组），点「✔ 完成」
   退出；在列表中选择某个分组后，「诊断分级与施肥映射设置」主表即显示并编辑该组的
   分级数量、累计占比、长势标签与施肥映射（公式 / 手动）；未分组区域沿用全局设置。
   各分组独立诊断后合并为单一处方图输出（分组原始输出保留在 `group_*` 子目录）。
5. **生成**：两遍分块流式处理，进度条实时展示。
6. **结果**：分级统计、阈值表、施肥映射、成果预览（诊断图 / 处方图，预览图下方展示统计：
   处方图施肥总量 / 处方图面积 / 平均每亩施肥量，诊断值总区间，总面积 / 感兴趣区域面积）。
   诊断图 / 处方图下方还有图面注记模块：田块面积、制图单位、制图时间（可编辑，自动记忆）
   与「长势等级」图例 / 「推荐施肥量」色温条；点「🖼 嵌入预览图」把注记绘制到预览图的白色边框区域内
   （宋体；两种图均加左右白边，诊断图顶边较高、处方图顶边较矮，
   说明文字与图面边缘对齐，不遮挡图面；源图过小时自动放大重渲染底图），
   点「⬇ 下载」导出嵌入后的 PNG。
   输出文件下载，以及可选的「按大疆模板替换处方图」工具。

选择「感兴趣区域制作」时，分位阈值仅在区域内有效像素上统计，诊断图与处方图
在区域外输出无效值（255 / NaN），标点经纬度与凸包顶点记录在输出元数据 `.json`
的 `roi` 字段中。

## 输入约定（重要修复）

原项目仅上传一张 `result.tif`（RGBA 预览图）就当作 B1–B4 参与诊断，其
第 3 波段实为蓝光、第 4 波段实为 Alpha 通道，诊断结果无意义。重构后**必须上传
4 张单波段通道图**，加上 1 张预览图，共 5 张同经纬度影像：

| 通道 | 文件名关键字 | 波段 | 说明 |
| ---- | ------------ | ---- | ---- |
| B1   | 含 `RedEdge` | 红边 | 参与校验（当前 8 个模型公式未直接使用） |
| B2   | 含 `Green`   | 绿光 | 参与诊断（如扬花期 NRI） |
| B3   | 含 `Red`     | 红光 | 参与诊断（NDVI/OSAVI/RVI 等） |
| B4   | 含 `NIR`     | 近红外 | 参与诊断 |
| 预览 | 不含任何关键字的 `result.tif` | — | 仅作整体浏览，**不参与诊断计算** |

注意：识别顺序先 `RedEdge` 后 `Red`（"RedEdge" 包含 "Red"），不区分大小写。
B1–B4 通道图不在界面中显示，仅用于计算；界面只展示预览图与成果图。

## 输出文件

每次运行生成独立目录 `workspace/outputs/<时间戳>/`：

| 文件 | 说明 |
| ---- | ---- |
| `result_diagnose_<期>.tif` | 分级诊断图（uint8，1–5 级，255=无效，内嵌 CRS） |
| `result_diagnose_<期>_value.tif` | 诊断值图（float32，无效=NaN） |
| `result_prescription.tif` | 处方图（float32，施肥量 kg/亩，无效=NaN） |
| `result_prescription_<宽度>m.tif` | 按所选栅格宽度聚合的重采样处方图（最终成果，如 `result_prescription_1m.tif`） |
| 同名 `.tfw` | 世界文件（设备定位用） |
| 同名 `.json` | 元数据（阈值、统计、格式说明） |

处方图输出格式按大疆智图兼容性排查结论（`debug_prescription.md`）执行：
单波段 float32、strip 存储、deflate 压缩、不嵌 CRS/NoData/GDAL 扩展标签、
无效像元写 NaN，配套同名 `.tfw`。

## 相对原项目的变化

### 修复的 bug

1. **输入模型错误**（核心修复）：不再接受单张 result.tif 当作四波段诊断；
   必须上传 4 张单波段通道图 + 1 张预览图，按文件名自动识别通道，并做
   同经纬度（CRS + 仿射变换）与尺寸一致性校验。
2. **分位数采样空间偏置**：原 `collect_diagnosis_samples` 在达到样本上限时
   直接停止遍历，样本集中在影像左上角，与其注释声称的「随机抽样」不符。
   现改为全图蓄水池均匀抽样（固定随机种子，结果可复现）。
3. **大影像内存溢出**：原 `dj2pr.py` 将整幅处方图读入内存
   （约 250MB 压缩的处方图解码后 6.7GB，实测 OOM）。现改为分块流式处理。
4. **web 化后的边界修复**：JSON 序列化 NaN、进度百分比溢出、输出文件名
   带后缀等（开发过程中发现即修）。

### 行为差异（有意为之）

* 诊断值图无效像元由 `255.0` 改为 `NaN`（不写 NoData 标签）。
* 施肥映射分级数量自动跟随所选生育期（成熟期为 4 级，不再套用 5 级映射表）。
* 原「处方图池化降采样（可选）」替换为地面栅格重采样：栅格宽度由用户在网页端
  选择（最低 1 m，默认 1 m），average 聚合（rasterio.warp，与 gdalwarp 同源内核，
  像元面积加权平均），像元尺寸按影像坐标系换算为真实地理地面距离
  （`config.json` 的 `resampling` 提供默认宽度与方法）。
* 原 CLI 交互全部由网页界面替代；`prescription.json` 不再被运行时改写。

## 感兴趣区域（ROI）实现说明

* **标点与凸包**：前端在预览图画布上记录标点，用 Andrew 单调链计算最小凸包
  并实时绘制；标点经纬度由预览图地理参考（result.tif 仿射变换 + 降采样比例）换算。
  点击已有标点（10 屏幕像素内）删除该标点并重算凸包，使凸包可内缩；
  撤销到"当前区域为空"时撤回最后一个已完成区域并恢复其标点继续编辑。
* **区域互斥**：新标点若落在任一已完成凸包内部（射线法判定）则拒绝。
* **服务端栅格化**：前端把凸包顶点经纬度随生成请求提交；服务端先将顶点重排为
  凸包顺序（防御乱序输入），再换算到诊断网格像素坐标，按分块窗口做扫描线
  偶奇填充（全图可达数十亿像素，掩膜不整图驻留内存）。
* **阈值与输出**：分位数阈值仅在 ROI 内有效像素上统计；诊断图 ROI 外为 255
  （nodata），处方图 ROI 外为 NaN；ROI 标点经纬度写入输出元数据。

## 配置要点（config.json）

* `server.port`：服务端口（默认 8765）
* `defaults.processing_block_size`：分块大小（默认 1024，内存占用约几十 MB）
* `defaults.max_quantile_samples`：分位数样本上限（默认 200 万；设为 0 表示全量）
* `stages`：8 个生育期的指数公式、诊断模型与分位断点（与原 `diagnose.json` 一致）
* `prescription.formula_mode`：施肥映射公式 Q_i = Q_b × [1 + (b − i) × k] 的默认参数
